# Совместный и менеджерский режимы «Колбасок»

## Цель

Добавить два самостоятельных представления одного бэклога:

1. **Режим команды** — безопасный просмотр по ссылке для любого зарегистрированного пользователя с авторскими комментариями к колбаскам.
2. **Режим менеджмента** — компактная презентационная шкала фич по командам, показывающая baseline, фактический прогресс и отклонения, но не внутреннюю операционную детализацию.

Основной режим владельца сохраняет весь существующий функционал: feature → role → sprint, прямое редактирование, загрузку, baseline и локальное undo удаления.

## Пользователи и права

### Владелец

- Полностью редактирует свой план.
- Создаёт, отзывает и перевыпускает ссылку общего просмотра.
- Задаёт правила включения ролей в менеджерский срок.
- Может оставлять, закрывать и удалять любые комментарии общего режима.

### Участник команды

- Регистрирует лёгкий аккаунт с именем и паролем; это имя видно у комментария.
- Открывает план только по активной ссылке и только в read-only режиме.
- Выбирает одну команду или все команды, а также предпочитаемый стиль отображения.
- Создаёт комментарии, вопросы и замечания на колбасках; закрывает или удаляет только собственные.
- Не получает API-прав менять план, baseline, роли, загрузку или настройки доступа.

### Доступ по ссылке

- Ссылка содержит криптографически случайный токен, привязанный к владельцу и одному бэклогу.
- Успешный вход обязателен: токен сам по себе не открывает данные анонимному посетителю.
- Отзыв делает токен недействительным сразу. Перевыпуск создаёт новый токен и инвалидирует старый.
- Токен не является идентификатором пользователя и не даёт доступ к списку других бэклогов.

## Режим команды

Маршрут вида `/share/<token>` показывает упрощённую рабочую поверхность.

- Верхняя панель: название бэклога, фильтр «Все команды / одна команда», выбор темы и короткое пояснение read-only режима.
- Центральная сетка: реальные колбаски по ролям и спринтам, включая фактические переносы, риски и baseline; скрываются кнопки редактирования, drag/resize, нагрузка и служебные настройки.
- Нажатие на колбаску открывает боковую панель комментариев к конкретному `epicId + segmentId`.
- Новый комментарий имеет тип `question | comment | issue`, текст и автора. Статус `open | resolved` отображается у каждого сообщения.
- Комментарии видят все участники с активной ссылкой. Автор или владелец могут удалить свой/любой допустимый комментарий соответственно; автор или владелец могут закрыть/переоткрыть комментарий.
- Смена темы является локальным предпочтением пользователя и не меняет план владельца.

## Режим менеджмента

Маршрут владельца и общего просмотра использует одно read-only представление. Владелец открывает его из переключателя «Сводно»/«Для менеджмента», участник — из режима команды, если владелец разрешил переключение.

### Композиция

- Строки сгруппированы по командам, как на референсе «БЭКЛОГ 2026».
- Сверху — кварталы и временная сетка; нижняя таблица загрузки, роли и технические этапы не показываются.
- Одна фича представлена одной компактной цветной полосой. Длинные названия сокращаются с полным title в подсказке.
- Серый контур baseline показывает обещанный на год диапазон всей фичи (`plannedFrom` → `plannedTo`) и лежит за фактической полосой.
- Командный цвет маркирует фичу как сейчас; статус фичи кодируется отдельным спокойным цветом, чтобы не смешивать команду и состояние.

### Менеджерский срок

Фактическое начало и окончание менеджерской полосы вычисляются только из сегментов, включённых в менеджерский расчёт.

1. Глобальное правило хранится по ролям: роль включена или исключена по умолчанию. Шаблон исключает «Бизнес» и «Груминг».
2. У отдельной колбаски есть точное переопределение `inherit | include | exclude`.
3. Итоговый диапазон — минимум `from` и максимум `to` только включённых сегментов.
4. Если включённых сегментов нет, отображается только baseline с подписью «Факт не начат».
5. Baseline никогда не входит в загрузку и не меняет фактические сроки владельца.

### Автоматический статус

Статус вычисляется без ручной разметки, относительно текущего спринта и baseline:

- **Готово** — все менеджерские сегменты завершены, а статус фичи `готово`.
- **В работе** — фактический диапазон пересекает текущий спринт и не просрочен относительно baseline.
- **Риск** — фактический старт позже baseline, фактический финиш позже baseline, либо baseline уже закончился, а фича не готова.
- **Предстоит** — включённые сегменты начинаются в будущем либо факта ещё нет.

При отклонении интерфейс показывает обе даты, например: «План: 12.04 · факт: 26.04», а не только цвет.

## Модель данных

### План

Существующие `Epic.plannedFrom/plannedTo` остаются baseline всей фичи.

Добавляются настройки владельца:

```ts
interface ManagementSettings {
  roleDefaults: Record<RoleId, boolean>; // true = учитывать в сроке
}

interface Segment {
  // существующие поля
  managementTiming?: 'inherit' | 'include' | 'exclude';
}
```

При нормализации старых планов `roleDefaults` строится из ролей: все `true`, кроме `business` и `grooming`; для уже сохранённых сегментов `managementTiming` равен `inherit`.

### Совместный доступ и комментарии

Эти данные хранятся отдельно от JSON плана, в пользовательской директории владельца:

```ts
interface ShareLink {
  tokenHash: string;
  createdAt: string;
  revokedAt: string | null;
}

interface BacklogComment {
  id: string;
  epicId: string;
  segmentId: string;
  type: 'question' | 'comment' | 'issue';
  text: string;
  authorId: string;
  authorName: string;
  createdAt: string;
  resolvedAt: string | null;
  resolvedBy: string | null;
}
```

Хэш токена хранится вместо сырого токена. При перевыпуске старый хэш заменяется. Комментарии не встраиваются в план, поэтому сохранение плана не перетирает обсуждение.

## API

Все ответы `no-store`; все мутирующие маршруты требуют валидную сессию.

### Для владельца

- `POST /api/share-link` — создать или перевыпустить токен; возвращает сырой URL единственный раз.
- `GET /api/share-link` — статус действующей ссылки без токена.
- `DELETE /api/share-link` — отозвать доступ.
- `GET /api/management-settings` и `PUT /api/management-settings` — правила ролей.

### Для участника по ссылке

- `GET /api/shared/:token/plan` — безопасное read-only представление плана после проверки сессии и токена.
- `GET /api/shared/:token/comments?epicId=&segmentId=` — комментарии колбаски.
- `POST /api/shared/:token/comments` — создать комментарий.
- `PATCH /api/shared/:token/comments/:id` — закрыть/переоткрыть, только автор или владелец.
- `DELETE /api/shared/:token/comments/:id` — удалить, только автор или владелец.

Сервер получает владельца по токену, проверяет доступ до чтения файлов и никогда не принимает `ownerId` от клиента.

## Обработка ошибок

- Неактивная/неверная ссылка: нейтральная страница «Ссылка недействительна или отозвана», без раскрытия существования владельца.
- Нет сессии: переход на вход с возвратом к текущему share URL после авторизации.
- План удалил сегмент, у которого были комментарии: комментарии сохраняются, но в UI показываются только в истории фичи для владельца; участнику не показывается «висячий» комментарий.
- Сбой отправки комментария: текст остаётся в поле, выводится понятная ошибка и кнопка повтора.
- Конфликт статуса комментария: сервер возвращает актуальную запись; клиент обновляет ленту.

## Безопасность и ограничения

- Токены генерируются `crypto.randomBytes(32)`, хэшируются SHA-256 или эквивалентной однонаправленной функцией с постоянным сравнением.
- Ограничение частоты: share-link generation, чтение по ссылке и создание комментария защищены rate limit по IP и пользователю.
- Текст комментариев рендерится как текст, без HTML.
- Share API возвращает только план владельца и не раскрывает e-mail/пароли/полный список пользователей.
- Старый basic auth прокси остаётся административным внешним барьером до отдельного решения владельца; публичный share-flow нельзя считать доступным извне, пока он включён.

## Компоненты

- `ShareSettingsPanel` — владелец создаёт/отзывает/копирует ссылку.
- `SharedBacklogPage` — route guard, фильтр команды, тема, режим команды/менеджмента.
- `SharedGrid` — read-only сетка факта и baseline.
- `SegmentCommentsPanel` — список и composer комментариев.
- `ManagementTimeline` — компактные фичи по командам, baseline и отклонения.
- `managementTiming.ts` — чистые функции фильтра сегментов, диапазона, статуса и пояснения отклонения.
- `shareStore`/серверные файловые функции — ссылки и комментарии изолированно от `plan.json`.

## Тестирование и приёмка

1. Незарегистрированный пользователь не получает план по share URL; зарегистрированный с активным токеном получает read-only данные.
2. Отзыв сразу блокирует старый URL; новый URL работает.
3. Участник не может вызвать владельческие `PUT /api/plan` и `PUT /api/management-settings`.
4. Создание, закрытие и удаление комментария проверяются для автора, другого участника и владельца.
5. Переключение команды и темы в shared mode не меняет `plan.json`.
6. Менеджерский диапазон исключает Business/Grooming по умолчанию, допускает глобальную смену и сегментное переопределение.
7. Baseline не меняет `computeLoad`, actual duration и детальный режим.
8. Фича со стартом позже baseline получает «Риск» и обе даты; фича без факта показывает baseline + «Факт не начат».
9. Read-only режим не содержит drag/resize, удаления, редактора фич и API-вызовов изменения плана.
10. Typecheck, production build, API smoke tests и браузерные сценарии проходят до релиза.

## Вне первого релиза

- Уведомления о новых комментариях.
- Вложения, упоминания и треды комментариев.
- Гостевой анонимный доступ.
- Ручное редактирование baseline через shared mode.
